# Ignite PR Checker

[English](README.md) · **Русский**

Небольшой сфокусированный инструмент для TeamCity-инфраструктуры в духе
[Apache Ignite](https://github.com/apache/ignite). Он хорошо отвечает на один вопрос — **какие тесты
мой pull request сломал на самом деле?** — и позволяет сразу действовать:

1. **Показывает настоящие блокеры** PR: тесты, упавшие в твоём прогоне и похожие на следствие
   *твоего изменения*; pre-existing и флакующие на мастере падения отфильтровываются как шум.
2. **Запускает прогоны** с той же страницы: всю цепочку RunAll или перезапуск только блокер-сьют
   (или одной сьюты), при спешке — в голову очереди.

➡ **Живой инстанс для контрибьюторов Apache Ignite: <https://ignite-pr-checker.is-a.dev>** — вход со своим ci2-токеном.

➡ **[Тур по возможностям со скриншотами](docs/features.ru.md)**

Это намеренно лёгкая, самообновляющаяся альтернатива легаси-боту
[ignite-teamcity-bot](https://github.com/apache/ignite-teamcity-bot): без базы данных и стейта,
за которым надо ухаживать, — тонкий слой над TeamCity REST API плюс тот единственный кусок логики,
который важен. Вердикт можно публиковать («виза») в JIRA-тикет PR-а — вручную, разово по завершении
прогона или автоматически для каждого своего прогона. Каждый пользователь работает под собственным
токеном TeamCity.

## Главная идея: что такое «блокер»?

Тест, упавший в последнем **RunAll** твоего PR, — **блокер** (сломан *твоим изменением*), только
если выполняется **всё** перечисленное:

- **Чист на мастере** — он **не** падает в последних `MASTER_HISTORY_DEPTH` (по умолчанию **100**)
  прогонах этого теста на базовой ветке. Любое падение там означает pre-existing или флаки, не твоя
  вина → отфильтровывается как шум (с указанием причины).
- **Падает на ветке устойчиво** — во всех последних `BLOCKER_FAIL_STREAK` (по умолчанию **3**)
  завершённых прогонах своей сьюты на ветке PR, без единого прохода в этом окне. Проход *на том же
  коде* означает, что падение вызвано не изменением:
  - упал только в самом последнем прогоне, а до этого проходил → отсев как *flaky on branch*;
  - падает последние 2+ прогона, но раньше проходил → отдельная карточка **«Recently started
    failing»** — свежая поломка «на карандаше», ещё не твёрдый блокер.

  Вердикт, ссылки и полоски истории всегда заякорены на **самый свежий завершённый прогон**.
- Если у теста **вообще нет истории на мастере**, он остаётся блокером («нельзя доказать, что
  pre-existing»).

Сьюты без надёжного прогона — ошибка компиляции, **таймаут, out-of-memory, краш JVM** или цепочка,
прерванная/отменённая на середине, — показываются как **broken suites**, а не разбираются на
каскадные падения; у прерванной цепочки — явный баннер *RunAll interrupted*. Пока более новый RunAll
ещё бежит (или закончился отменой), результаты его завершившихся сьют **вливаются в вердикт вживую**
— не нужно ждать всю ~4-часовую цепочку.

У каждого блокера — **полоска pass/fail** его завершённых прогонов на ветке (зелёный = прошёл,
красный = упал, старые → новые) — как у бота, но вычисляется на лету.

Всё остальное выводится отдельно как отфильтрованный шум, каждый пункт — с причиной. История
читается вживую из TeamCity REST API; поддерживать хранилище не нужно.

## Что на странице

- Левая панель — **открытые PR** репозитория (свежеобновлённые сверху); клик — анализ, любой номер
  в URL (`?pr=12345`) открывает PR напрямую, даже если его нет в списке.
- Блокеры сгруппированы **по сьютам** (заголовок сьюты ведёт на её прогон в CI); каждый тест —
  ссылка прямо в падение **в последнем завершённом прогоне**.
- **Триггеры**: `RunAll` (*обычный* или *в голову очереди*), пара **Rerun / Rerun top** у каждой
  секции (битые сьюты, блокеры, «недавно посыпался», отсев) и у каждой отдельной сьюты, живой
  список твоих прогонов с queue-aware ETA и **Cancel all**.
- **JIRA-виза**: вердикт постится комментом в `IGNITE-XXXXX`-тикет PR-а — в один клик, разово по
  завершении текущего прогона (**Auto visa**) или постоянной опцией в настройках (⚙) для **каждого**
  своего прогона. JIRA PAT ездит в шифрованной куке; для отложенных вариантов хранится шифрованным
  только до поста визы / пока опция включена.
- Публичная **[страница статуса](src/main/resources/static/status.html)** (`/status.html`) с
  метриками сервиса: вызовы TeamCity/GitHub **по категориям за последний час**, поминутный график,
  успешность и латентность, JVM/кэш-внутренности и индикатор **health** со свежими WARN/ERROR из лога.

## Архитектура

Один Spring Boot-процесс, без базы данных:

| Компонент | Ответственность |
|---|---|
| `TcClient` | Тонкая обёртка над TeamCity REST API: последний завершённый RunAll, разворот snapshot-зависимостей, упавшие тесты, история теста на мастере, прогоны на ветке, триггер/отмена билдов. Каждый вызов идёт с токеном вызывающего. |
| `ChainCollector` | Разворачивает композитный RunAll в сьюты-зависимости и собирает упавшие тесты (плюс «сломанные» сьюты без тестов и состав прогона ran/reused). |
| `BlockerAnalyzer` | Классификатор: чист-на-мастере + устойчивое падение в последних N прогонах ветки → блокер / «недавно посыпался» (watch) / шум; пер-тестовые запросы параллелятся; результаты кэшируются. |
| `AnalysisCache` / `TtlCache` | In-memory-кэши (результат на билд, история теста на мастере), общие для всех пользователей и PR. |
| `Warmer` / `TokenPool` | Держит свежие PR предпрогретыми в фоне, распределяя нагрузку по токенам залогиненных пользователей; **cache-aware** (пересчитывает только PR, чей RunAll изменился). |
| `RunDeltaStore` / `FlakyStats` / `RerunTracker` | Дельта и тренд блокеров между прогонами; персистентная очередь «чинить мастер»; живые статусы queued/running у перезапусков. |
| `CacheStore` / `SnapshotCache` | Снапшоты кэшей на диск: рестарт/редеплой стартует тёплым, не долбя TeamCity заново. |
| `GithubClient` | Список открытых PR для навигации (кэшируется, чтобы не выесть rate-limit API). |
| `Metrics` / `LogTracker` / `StatusController` | Публичная страница статуса (скользящие часовые метрики вызовов + здоровье по логу). |
| `UpdateService` | Самообновление: проверяет релизы на GitHub и по запросу меняет jar и перезапускается. |
| `JiraClient` / `VisaService` / `VisaSubscriptions` / `StandingVisas` | JIRA-«виза»: собирает вердикт в wiki-разметке и постит в тикет — вручную, разово при финише отслеживаемого прогона или периодическим свипом для всех прогонов подписанного пользователя (токены шифруются и хранятся только пока нужны). |
| `UserDirectory` | Кто пользовался инструментом (имя, активность, логины) — вкладка **Users** на статус-странице. |
| Веб-контроллеры | `/api/analyze`, `/api/refresh`, `/api/causes`, `/api/delta`, `/api/progress`, `/api/trigger`, `/api/rerun-suite(s)`, `/api/runs`, `/api/cancel-all`, `/api/jira-visa`, `/api/auto-visa(-all)`, `/api/users`, `/api/restart`, `/api/prs`, `/api/config`, `/api/status`, `/api/version`, `/api/update`, `/api/login`·`/logout`·`/me`, … |

## Аутентификация

**В конфиге нет учёток.** Каждый пользователь входит со **своим** токеном TeamCity (TeamCity:
*Profile → Access Tokens*). Токен валидируется и шифруется (AES-GCM) в **HttpOnly-куку сессии** —
сервер не хранит сессии, поэтому логины переживают рестарты/редеплои, а вход действует до выхода.
Все вызовы TeamCity идут под правами этого пользователя. Раздавай приложение по HTTPS (токен ездит
в куке) и включи `SESSION_COOKIE_SECURE=true`.

## Конфигурация

В конфиге — только **несекретные, общие для деплоя** настройки; см.
[`application.yml`](src/main/resources/application.yml). Дефолты нацелены на CI Apache Ignite.
Переопределяются переменными окружения:

```bash
export TC_BASE_URL="https://your-teamcity-host/"        # по умолчанию: https://ci2.ignite.apache.org/
export TC_RUN_ALL_BUILD_TYPE="IgniteTests24Java8_RunAll"
export MASTER_HISTORY_DEPTH=100                         # прогонов мастера на тест для правила блокера
export BLOCKER_FAIL_STREAK=3                            # подряд упавших прогонов ветки для блокера
export APP_PUBLIC_URL="https://your.host"               # абсолютные ссылки в JIRA-визах
export GITHUB_REPO="apache/ignite"                      # чьи открытые PR показывать в навигации
export GITHUB_TOKEN=...                                 # опционально: поднять лимит GitHub API (60 -> 5000/ч)
export SESSION_SECRET=...                               # стабильный секрет, чтобы логины переживали рестарты (install.sh генерирует)
export SESSION_COOKIE_SECURE=true                       # включить за HTTPS (например, за Caddy)
```

## Установка / обновление на сервере (одна строка)

Debian/Ubuntu, под root. Та же команда и ставит, и обновляет до последнего релиза (конфиг
`/etc/ignite-pr-checker/env` сохраняется):

```bash
curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/ignite-pr-checker/main/install.sh | sudo bash
```

Она ставит JRE, сервисного пользователя `prc`, `systemd`-юнит (через маленький `run.sh`, который
заодно выполняет самообновления), скачивает последний релизный jar и запускает сервис. Секретов
настраивать не нужно — открой сайт и войди со своим токеном TeamCity. Поставь за HTTPS (например,
Caddy) с `SESSION_COOKIE_SECURE=true` и включи сжатие на прокси — JSON анализа весит сотни КБ и
жмётся ~10×; на маленькой машине это разница между мгновенной и вязкой загрузкой. Минимальный
`Caddyfile`:

```
your.host {
	encode zstd gzip
	reverse_proxy localhost:8080
}
```

Дальше новые релизы подхватываются из UI: в шапке появляется кнопка **Update to vX.Y.Z**; любой
залогиненный пользователь жмёт её — сервис сам меняет jar и перезапускается, доступ к серверу не
нужен.

## Управление установленным сервисом

`install.sh` регистрирует `systemd`-сервис **`ignite-pr-checker`**, включает его (автозапуск при
загрузке) и запускает под пользователем `prc` на порту **8080**. Управление — обычным `systemctl`:

```bash
sudo systemctl status  ignite-pr-checker    # работает?
sudo systemctl start   ignite-pr-checker    # запустить
sudo systemctl stop    ignite-pr-checker    # остановить
sudo systemctl restart ignite-pr-checker    # перезапустить (например, после правки конфига)
```

Логи:

```bash
journalctl -u ignite-pr-checker -f
```

Конфигурация живёт в **`/etc/ignite-pr-checker/env`** (после правки — перезапустить сервис). Само
приложение — в `/opt/ignite-pr-checker` (`app.jar`, запускается через `run.sh`). Обновить бинарь —
кнопкой **Update to vX.Y.Z** в UI или повторным запуском установочной строки; конфиг сохраняется
в обоих случаях.

## Релизы

Релизы собирает CI. Выпустить — запушить тег:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Workflow [`release`](.github/workflows/release.yml) собирает fat-jar (вшивая тег как версию
приложения) и публикует его ассетом GitHub Release с именем `ignite-pr-checker.jar`, откуда его
всегда берут `install.sh` и самообновление (`/releases/latest/download/`).

## Сборка и запуск локально

Нужен JDK 17.

```bash
./gradlew bootRun
# затем открой http://localhost:8080
```

Для быстрых итераций на своём тестовом хосте есть [`deploy.sh`](deploy.sh): собирает jar локально
и заливает по SSH (`build → scp → restart`) без выпуска релиза.
