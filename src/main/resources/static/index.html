      Create a token
      What the checker does with your token
      • Your browser keeps it in an encrypted session cookie.
      • The server keeps it in memory for up to an hour after your last request, or until you log out. The host's swap can write that memory to the disk.
      • After login, the ⚙ menu has options that work while this page is closed. While one is on, the server stores the token encrypted, until you turn them all off. Copies stay in server backups for 2 days. With any option other than PR commands on, the server also keeps using the token to read from TeamCity, to check open PRs for everyone.
      • Log out ends your login in this browser. ⚙ lists your logins in other browsers and can end them. A login left unused for 400 days ends too.
      No ci2 account or token yet?
      1. Register an account on ci2, the TeamCity of Apache Ignite.
      2. Create an access token there: Profile → Access Tokens (“Create a token” above opens it).
      3. The token acts with your account's rights. Reading verdicts needs only view access. “Run” and “Rerun” need the right to run builds. “Run at top” and “Rerun at top” also need the right to reorder the build queue. Without it, TeamCity queues them at the end. “Cancel my runs” needs the right to stop builds and remove them from the queue.

      What the badges mean
      • ✓clean — a run of the PR's current code blamed nothing on it
      • !started failing — no blockers yet, but tests started failing on the code the run tested; a re-run shows whether they are blockers
      • ?not proven clean — no blockers found, but the run can't prove the PR clean
      • …checking — only for the PR open on the page: checking that the run tested its latest commit
      • 2blockers — tests the PR most likely broke
      • my runmy run — you started its latest RunAll, or for a Python client PR, its latest run of the suite
      • no badge — no verdict yet
